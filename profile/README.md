<p>真正要拍板的时候，问题往往不是「住宅 IP 好不好」，而是「我这几台机器、这几个号，出口该怎么切」。这篇不铺原理，只给一份能照着走完的决策清单：先定三件事、再排出口、然后做绑定核对、跑验收动作、最后设换方案的触发条件。五步走完，配置基本就定型了。文中出现的价格与阈值为经验区间，仅供参考，实际以线路商报价和自身账号规模为准。</p>
<h2>一、拍板前先把三件事定下来</h2>
<p>这三件事没定，后面所有关于「一条线跑几个号」的讨论都是空谈。先把它们写在纸上，再往下看。</p>
<h3>账号总数与未来三个月的增长节奏</h3>
<p>当前五个号和未来二十个号，是两套完全不同的方案。按条计费的独享出口，一次性买二十条和先买五条再补，单价差别不大，但闲置成本差很多。建议按「三个月内确定会开的号数」上浮两成备线，剩下的用临时线路补。</p>
<h3>每个号每天的实际在线时长</h3>
<p>一天开两小时和全天挂着的号，对出口的要求不一样。全天在线的号，出口一旦抖动就立刻体现在会话上，最好配一条能自动重拨的备用线；每天短时使用的号，稳定性要求可以放宽一档，用共享池也能接受。</p>
<h3>哪些号是不能出事的</h3>
<p>把号分成三档：主力号（有付费订阅、有历史对话）、一般号（在养、还没沉淀）、试验号（随时可弃）。主力号必须一条线一个号，不做任何共用；一般号可以两号一条线但要有隔离手段；试验号用池子轮换即可。分档这一步省不得，它直接决定预算怎么分配。</p>

<h2>三、账号与环境的绑定要逐项核对</h3>
<p>出口分好了，还有一半工作在于「环境」——浏览器指纹、时区、语言、Cookie 容器。出口不同而指纹相同，等于换了个门牌号却还是同一张脸。</p>
<h3>指纹容器必须一号一个</h3>
<p>用指纹浏览器的话，一个号对应一个独立 Profile，User-Agent、Canvas、WebGL、字体列表都由容器隔离，不要在同一个容器里切换账号。容器名建议直接用账号编号，避免后期对不上。</p>
<h3>时区与语言跟随出口所在地</h3>
<p>家宽出口在洛杉矶，容器时区就该是 America/Los_Angeles，语言 en-US。时区与出口错位六小时以上，是最容易被记录下来的不一致项，比指纹碰撞更常见。</p>

<h2>四、上线前要跑完的验收动作</h2>
<p>配置完不等于能用，下面四个动作建议每条线都跑一遍，全程十五分钟以内。</p>
<p>第一，查出口归属。用线路商提供的查询接口或公开的 IP 信息页，确认 ASN 属于住宅宽带运营商而不是机房，归属城市与购买时标注一致。</p>
<p>第二，查 DNS 与 WebRTC 泄漏。在容器内打开检测页，确认 DNS 解析走的是出口侧，WebRTC 暴露的本地地址不是真实内网段。</p>
<p>第三，跑一次登录全流程。从登录页到进入对话，观察是否出现验证、是否要求二次确认，把耗时记下来作为基线。后续同一账号耗时突然拉长，就是早期信号。</p>
<p>第四，交叉验证不串线。同时开两个号的容器，各发一句带编号的话，确认两边的会话历史互不可见，代理日志里两条会话的出口 IP 不同。</p>

<h2>常见问答</h2>
<h3>一条家庭宽带上能不能挂两个号？</h3>
<p>答：技术上可以，但要看这两个号的关系。同一个人、同一批注册、同一业务用途的号，挂在一起风险叠加；不同批次、不同用途的号，共用一条家宽反而更像正常家庭。判断标准是「对外看起来是否像两户人家」，而不是「能不能连上」。</p>
<h3>家庭住宅 IP 和双 ISP 住宅 IP 要选哪个？</h3>
<p>答：看用途。需要长期固定、对外演示、给客户看的，选原生家宽，归属信息最像普通家庭；需要规模铺开、成本可控的，选双 ISP，归属记录干净且供给稳定。两者可以混用，主力号用前者，一般号用后者。</p>
<h3>出口换了，账号资料要不要跟着改？</h3>
<p>答：不建议频繁改。账号的注册地、语言、常用时段是一套整体，出口迁移最好一次性迁到位，然后长期不动。频繁改资料本身就是一个异常特征，比出口变化更显眼。</p>
<h3>怎么确认两个号真的没有串线？</h3>
<p>答：做双盲测试。两个容器各发一句唯一编号的内容，互相检查历史里是否出现对方的内容；同时拉代理侧的连接日志，确认两条会话的源 IP 不同、会话 ID 不同、时间不重叠。两项都对上，才算验证通过。</p>
